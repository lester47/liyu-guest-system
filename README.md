# 鯉魚國小來賓通報系統

南投縣鯉魚國小活動（例如「115鯉魚市集」）使用的來賓報到與介紹系統。接待老師一按，司儀和校長馬上在介紹台看到來賓，並依優先順序排好。

網站本體是純靜態網頁，可以同時放在 **GitHub Pages** 和 **Vercel**；資料存在 **Firebase**（免費方案即可）。

## 功能

| 頁面 | 給誰用 | 做什麼 |
|---|---|---|
| 首頁 `index.html` | 所有人 | 顯示「來賓自助報到」QR Code；工作人員從這裡以 Google 帳號或帳號密碼登入 |
| 來賓自助報到 `checkin.html` | 來賓 | 不用登入，填頭銜、姓名、身分後送出，先進入「待確認」；也可放在門口平板 |
| 接待報到 | 接待老師 | 上方固定工作台（搜尋全部來賓並顯示未報到／已報到、臨時來賓、自助待確認入口）、確認或刪除自助報到、掃來賓 QR 一鍵報到、預約名單四個頁簽、設定第一優先、撤回；每筆通報顯示「傳送中 → ✓ 已送達介紹台」，斷網時顯示「尚未送達」並在恢復後自動補送 |
| 介紹台 | 司儀、校長 | 頂端放大顯示「下一位」；新到的第一優先只跳出提示、由司儀決定何時切換；按「介紹完畢」後 10 秒內可撤銷；待介紹分四個頁簽，依「第一優先 → 身分 → 到場先後」排序，可拖曳調整、分頁；常駐顯示連線狀態與資料最後更新時間 |
| 系統管理 | 系統管理者 | 待核准的申請（一鍵設為管理者／工作人員）、批次加入多個 email 或從 Excel／CSV 匯入、權限總覽（切換身分、移除）、常用後台連結 |
| 名單與 QR | 管理者 | 匯入 Excel／CSV、手動貼上名單、產生並下載來賓 QR 總表、活動設定、管理帳號與權限；**活動紀錄**：匯出 CSV、結案封存並開始下一場、切換回已結案的活動 |

**報到序號**：像醫院掛號一樣，每位來賓報到時依報到先後取得本場活動的序號（001、002…），顯示在接待頁、介紹台的「下一位」與佇列卡片、已介紹清單與 CSV 匯出。斷網時報到的來賓會在網路恢復後依報到時間補上號碼；自助報到的來賓在老師確認後，手機畫面會直接顯示自己的號碼。撤回報到的號碼不會再用；結案後下一場從 001 重新開始。四個身分頁簽各有顏色：長官 靛藍、貴賓 橘、家長 綠、其他 紫。

來賓自助報到的資料不會直接上介紹台：老師在「接待報到」的待確認區看過、可修改頭銜姓名後按「確認」才送出；惡作劇直接刪除。若姓名和預約名單中某一位相同，確認時會合併成同一筆。

## 權限分三層

| 身分 | 誰 | 可以做 |
|---|---|---|
| 系統管理者 | 一人（在 `firestore.rules` 指定） | 管理者能做的全部，再加上**決定哪些帳號是管理者**；無法從網站被移除 |
| 管理者 | 主任、承辦老師 | 管理工作人員帳號、活動設定、匯入／貼上／刪除名單、結案封存與切換活動、下載 QR，以及所有接待工作 |
| 工作人員 | 接待老師、司儀、校長 | 接待報到、確認自助報到、臨時來賓、介紹台；不能匯入、刪除預約名單或改設定 |

權限寫在 Firestore 安全規則裡，由伺服器檢查；即使有人修改網頁程式，也無法越權。

## 第一次設定（約 20 分鐘）

### 步驟 1：建立 Firebase 專案

1. 到 <https://console.firebase.google.com/>，用學校的 Google 帳號登入，按「建立專案」，名稱例如 `liyu-guest`。Google Analytics 可以關掉。
2. 專案建好後，在首頁按 **`</>`（網頁）** 新增應用程式，暱稱隨意，**不用**勾 Firebase Hosting。
3. 畫面會出現一段 `const firebaseConfig = { ... }`，把大括號裡的內容複製下來，貼到本專案的 **`js/config.js`**，取代裡面的範例值。

### 步驟 2：開啟登入方式

Firebase 主控台左側 →「Authentication」→「開始使用」→「Sign-in method」：

- 開啟 **Google**（支援電子郵件選你的帳號）
- 開啟 **電子郵件/密碼**（Email/Password）：給沒有 Google 帳號的老師用。「電子郵件連結」不用開
- 開啟 **匿名**（Anonymous）：來賓自助報到要用

注意：「Authentication → 設定 → 使用者動作」裡的「**啟用建立功能（註冊）」必須保持勾選**。關掉它會讓 Google 第一次登入和來賓匿名報到都失敗（錯誤代碼 `auth/admin-restricted-operation`）。即使有人自行建立帳號，安全規則也會要求 email 已驗證且在權限名單上，否則讀不到任何資料。

### 步驟 3：建立資料庫並貼上安全規則

1. 左側「Firestore Database」→「建立資料庫」→ 位置選 **`asia-east1`（台灣）** →「以正式版模式啟動」。
2. 打開本專案的 **`firestore.rules`**，把第 11 行的 `請改成系統管理者的電子郵件@gmail.com` 改成**你自己的 Google 帳號**（全部小寫）。
3. 回到 Firebase 主控台，切到「規則」分頁，把修改後的 `firestore.rules` 全部內容貼上，按「發布」。

### 步驟 4：放到 GitHub，開啟 GitHub Pages

1. 在 GitHub 建立一個新的 repository（例如 `liyu-guest-system`），把本資料夾的所有檔案上傳（包含 `.github` 資料夾）。
2. repository 的「Settings」→「Pages」→「Build and deployment」→ Source 選 **GitHub Actions**。
3. 到「Actions」分頁等「部署到 GitHub Pages」跑完（約 1 分鐘），網址會是  
   `https://你的帳號.github.io/liyu-guest-system/`

### 步驟 5：同步到 Vercel

1. 到 <https://vercel.com/>，用 GitHub 帳號登入 →「Add New… → Project」→ 選剛剛的 repository →「Import」。
2. Framework Preset 選 **Other**，Build Command 和 Output Directory 都留空 →「Deploy」。
3. 之後每次推送到 GitHub 的 `main` 分支，**GitHub Pages 和 Vercel 會同時自動更新**，兩個網址內容永遠一致。

### 步驟 6：把網址加入 Firebase 授權網域（很重要）

Firebase 主控台 →「Authentication」→「設定」→「已授權的網域」→「新增網域」，把兩個網址的網域都加進去：

- `你的帳號.github.io`
- `你的專案.vercel.app`（若有自訂網域也要加）

沒加的話，按「以 Google 帳號登入」會出現「未授權的網域」。

### 步驟 7：系統管理者第一次登入，設定權限

1. 用步驟 3 填入規則的帳號登入網站，系統會自動建立帳號名單，你就是**系統管理者**。
2. 到「名單與 QR」→「帳號與權限」：
   - 輸入主任或承辦老師的帳號，按「**加為管理者**」（只有系統管理者看得到這顆按鈕）。
   - 輸入接待老師、司儀、校長的帳號，按「**加為工作人員**」（管理者也能做）。
3. 不在名單上的帳號登入後會看到「申請使用權限」按鈕；老師按下後，申請會出現在你的「系統管理」分頁，按「設為管理者」或「設為工作人員」即可。

**用帳號密碼登入的老師**：先到 Firebase 主控台「Authentication → 使用者 → 新增使用者」，輸入老師的電子郵件與一組初始密碼，再把同一個電子郵件加到網站的權限名單。老師第一次登入時，系統會寄驗證信，點完連結才能使用；之後可用「忘記密碼」自行改密碼。

## 活動當天怎麼用

1. **活動前**：在「名單與 QR」匯入預約名單（可按「下載範本」照格式填，或用 Google 表單收集後下載成 Excel），下載 QR 總表印在邀請卡或名牌上；首頁的自助報到 QR 印出來貼在入口。
2. **接待桌**：老師用手機掃來賓的 QR，按「報到」或「第一優先」；沒有 QR 的來賓用「臨時來賓」通報；畫面上方出現「待確認的自助報到」時，看一眼按確認。
3. **來賓自己來**：掃入口的自助報到 QR 填寫，或在門口平板打開 `checkin.html` 填寫。
4. **介紹台**：平板或筆電開「介紹台」，助手依序介紹，介紹完點卡片；要調整順序就拖曳左側 ⋮⋮。
5. **活動後**：管理者在「名單與 QR」→「活動紀錄與匯出」按「結案封存，開始下一場」，當天的報到與介紹紀錄會封存起來（可隨時匯出 CSV 或切換回來），目前名單清空，接著就能匯入下一場的名單。不再需要的紀錄，系統管理者可以刪除。

「清空名單」只在還沒有任何人報到時才會出現（例如匯錯檔案），避免誤刪活動紀錄。

## 更新安全規則（每次 firestore.rules 有更新都要做）

「結案封存」用到 `archives`、「報到序號」用到 `settings/counter`，都要把新版 `firestore.rules` 貼到 Firebase 才能用；沒更新前，報到照常，只是不會產生序號、活動紀錄讀不到。

1. 打開 GitHub 上的 [firestore.rules](https://github.com/lester47/liyu-guest-system/blob/main/firestore.rules)，按右上角「複製原始檔」圖示（Copy raw file）。
2. 打開 [Firebase 安全規則頁](https://console.firebase.google.com/project/liyu-guest/firestore/databases/-default-/rules)，把編輯框內容全部選取刪掉，貼上剛剛複製的內容。
3. 按上方「發布」。

## 上線前驗證安全規則（建議）

在 Firebase 主控台「Firestore Database → 規則 → 規則測試區」(Rules Playground) 試這幾項，結果都應該符合：

| 模擬情境 | 動作 | 應該 |
|---|---|---|
| 未登入 | 讀取 `guests/任一筆` | 拒絕 |
| 未登入 | 讀取 `settings/event` | 允許 |
| 匿名登入（UID 填 `abc`） | 建立 `guests/abc`，status 為 `review`、source 為 `self` | 允許 |
| 匿名登入（UID 填 `abc`） | 建立 `guests/xyz` | 拒絕 |
| 匿名登入 | 建立 status 為 `arrived` 的資料 | 拒絕 |
| 工作人員帳號 | 讀取 `guests` | 允許 |
| 工作人員帳號 | 建立 source 為 `import` 的資料 | 拒絕 |
| 管理者帳號 | 修改 `settings/staff` 的 admins | 拒絕 |
| 系統管理者帳號 | 修改 `settings/staff` 的 admins | 允許 |
| 工作人員帳號 | 建立 `archives/任一筆` | 拒絕 |
| 管理者帳號 | 刪除 `archives/任一筆` | 拒絕 |

模擬 Google 帳號時，驗證提供者選 `google.com`，並在權杖中加入 `email` 與 `email_verified: true`。

## 換一所學校使用

只要改 `js/config.js` 的學校名稱與 Firebase 設定、`firestore.rules` 的系統管理者電子郵件，並用自己的 Firebase 專案（每所學校的資料彼此獨立）。若修改了來賓身分 `CATS`，`firestore.rules` 裡 `validSelf()` 的身分清單也要一起改。

## 常見問題

- **Firebase 設定放在 GitHub 公開安全嗎？** 可以。`apiKey` 本來就會出現在網頁裡，資料安全靠 `firestore.rules`：只有權限名單上、電子郵件已驗證的帳號能讀寫名單；來賓只能新增一筆待確認報到，讀不到任何人的資料。
- **登入出現 `auth/admin-restricted-operation`？** 到「Authentication → 設定 → 使用者動作」把「啟用建立功能（註冊）」勾回來並儲存。
- **為什麼不用一組共用密碼？** 網站是公開的靜態網頁，在網頁裡檢查密碼等於把密碼寫在公開的程式碼裡，任何人都看得到。每位老師用自己的帳號，離職或外流時只要從名單移除即可。
- **有人亂填自助報到怎麼辦？** 自助報到一律先進待確認，老師按確認才會上介紹台，司儀不會唸到惡作劇的內容。每次送出都會換一個匿名身分，一個身分只能送一筆。
- **系統管理者要換人？** 修改 `firestore.rules` 第 11 行的電子郵件並重新發布，新的系統管理者登入後就會接手。
- **會不會要錢？** 一場幾百人的活動遠低於 Firebase 免費額度（每天 5 萬次讀取、2 萬次寫入）。GitHub Pages 與 Vercel 個人方案也免費。
- **手機用 LINE 開啟無法登入？** LINE 內建瀏覽器會擋 Google 登入，請點右上角選「用預設瀏覽器開啟」。來賓自助報到不需要登入，不受影響。
- **介紹台一個畫面看得到幾位？** 10 吋平板橫放約 6～7 位，直放約 9～10 位；待介紹每頁 8 位，已介紹每頁 15 位。
